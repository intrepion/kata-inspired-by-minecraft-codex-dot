# Hearthwild acceptance criteria
An original peaceful voxel glade, private repository, no deployment. A finite seeded 40×40×24 world supports walking, gravity, jumping, targeting within five blocks, mining finite resources and placing carried blocks. Bedrock and bounds are immutable. Placement rejects player overlap and occupied cells. Mining stone requires a crafted pick. Four wood make eight boards; two wood and three stone make a pick; two boards and one stone make two glow blocks. Gather → craft → shelter walls and roof → light completes the opening journey. Inventory transactions never underflow or duplicate. Hotbar, inventory, pause, settings, recovery, documented controls, keyboard camera fallback and touch controls. Validated versioned saves persist edits, inventory, progression and safe player position. Corrupt saves fail safely. Original procedural textures and synthesized audio. Verify public model APIs and browser journey, persistence, collision, menus and responsive layout.

## Delegated decision tree and skill adaptation
The user explicitly delegates recommended decisions and forbids design questions. Round 1: browser TypeScript/Three.js, peaceful first person, finite glade. Round 2: deterministic world + sparse edits, atomic transactions, local validated save version 1. Round 3: free crafting panel, permanent pick, shelter milestone (six boards and one glow placed), pointer lock with arrow-key fallback, touch pad. All decisions accepted under delegated authority; no artificial confirmation round. TDD seams: World (determinism/bounds/edit), Game (resource/crafting/placement), save codec (validation/roundtrip), collision (player occupancy). These test rules miss rendering/input integration, covered in actual browser. Code-review baseline is initial docs commit; independent standards and spec agents after implementation. No issue tracker: this file is source of truth.
